# Protocol deviations and disclosures (must appear in REPORT.md)
Collected at M3 (T+14h15) by an independent retrospective agent; maintained by the PI.

1. **The TreeFam-A dev split was created after QfO peek 1** (peek 1 cafe3f5 → split f65d5b7). Peek 1 had already shown aggregate TreeFam-A and SwissTree recall, and that motivated the recall work. So dev/test is not blind in the DESIGN §4 sense. CORRECTION (verification pass 2): TreeFam-A **test-family** scores WERE computed at the logged peek 2 (results/qfo_peek2/treefamA_dev_test.json; accurate .580/.913, fast .605/.914), on PI authorisation, before the freeze tag. They did not drive any tuning (the presets were fixed before peek 2 and only the freeze followed), but dev/test is not blind.
2. **Heavy dev reuse:** OrthoBench dev has 243 runs on 34 RefOGs, and synteny parameters, local trees, FastTree, the presets and deep absorption were all selected on it. Dev numbers (79.7 vs OrthoFinder 70.5) are optimistic; the comparator was not tuned. Claims rely on OrthoBench **test** only.
3. **Deep-node threshold** (median seed −ln S ≥ 1.5) was defined and tuned on QfO TreeFam-A dev. No OrthoBench node qualifies, so it is QfO-specific and untested on OrthoBench.
4. **The S0 completeness target (≥95%) was missed:** dev 0.794, test 0.722, against a sequence-similarity ceiling ≈0.82. Recorded as a deviation; test completeness was logged.
5. **Non-inferiority on recall failed at peek 1** (TreeFam-A TPR .55 vs OrthoFinder .74); the final result must be reported against the pre-registered rule as it stands.
6. **Comparator rows** are published OpenEBench values, produced under other conditions. FastOMA benefits from the OMA database. Our first local FastOMA OrthoBench run (dev 29.6) was at first thought misconfigured. It was later traced to a FastOMA 0.5.1 gene-dropping bug with correct inputs (see #19).
7. **Design review round 3 was not run** (deferred, then superseded by data-driven reviews). The freeze moved from T+36h (DESIGN §7) to T+20h, to leave time for evaluation and review.
8. **Post-hoc redesigns.** Constrained synteny replaced the additive bonus after it failed. The micro → macro pair-F1 switch was made on dev. Shuffled-control spans are ±1–3 OG-F, so OG-level synteny gains of +4–7 are moderate evidence. VGNC PPV .982 suggests vertebrate over-merging.
9. **No claim was independently verified before M3.** Independent verification of CLAIMS.md is scheduled after the freeze. G-STD2/STD tests are run once, on the frozen config.
10. **Adoption rules were first checked only on the fast preset.** so_struct passed on fast and failed on accurate; the presets now differ in options (each adopted on its own base).
11. **The merge output depends slightly on Newick child order** (same topology, different child order → 18 OrthoBench OGs differ). Determinism holds for a fixed input file. Found in the final evaluation, after the freeze; not fixed.
12. **The synteny OG-level gain on OrthoBench dev (+4.4 OG-F) did not replicate on OrthoBench test** (−0.1 when removed). Report the synteny effect as dev-only at OG level; pair-level and QfO effects separately.
13. **Early exposure of test RefOGs** (found by independent verification): before the homology-component split, three S0 configs (commit 6711002) were scored per RefOG on the old random split's dev half; 16 of those RefOGs are in the current test set. Impact is likely small (only early S0 choices; the new split was rule-based with a fixed seed), but test is not perfectly blind.
14. **Runtime comparison is loose:** Ancestra ran at 10–12 threads, competitors at 8, on a shared node (load 20–65); DESIGN asked for 24 threads on an idle node. CPU-h is the fairer comparison. Gene-order table building (one-off parsing of GFF) is not included in Ancestra's 3.9 CPU-h.
15. **Exploratory status:** the 11 OrthoBench-test ablations and all QfO ablations have no multiple-testing correction; they are exploratory. "Precision comparable" at QfO peek 1 should read "inconclusive (no CI)". The S4 verdict "keep NJ" was superseded by the later FastTree merge arm (adopted on dev by its own rule).
16. **Commit-ID bookkeeping:** freeze.json was written one commit before the freeze tag; the code (ancestra/*.py) is byte-identical across 6c593a8, 71117bf (tag freeze-v1) and f7bcddc (cited in test_log).
17. **The QfO ablation CIs reported by the official test (±0.006) ignore within-family clustering of pairs.** Family-level bootstrap (1,108 families) gives: no gene order −0.012 [−0.028, +0.001]; ASTRAL-Pro +0.028 [−0.009, +0.077]; FastME +0.022 [−0.001, +0.045]. So no gene-order effect on QfO recall is supported.
18. **Wording corrections:** "STD comparable" had no CI; on STD-Euk, Ancestra is worse than OMA, Hieranoid and InParanoid. VGNC PPV (.982) is not lower than OMA's (.979–.980). The GO/EC "±" in qfo_final/summary.md is 1.96×SEM, not SEM. test_log commit IDs differ from the run manifests (the code is identical).
19. **OMA comparators were added after the freeze at user request** (post-freeze, compared with frozen outputs only). The OMA-browser-HOG OrthoBench conversion was first scored with a wrong labelling rule (test 45.5) and then corrected (test 60.4). Both are recorded in bench_repo/results/orthobench_competitors/oma_browser/. OMA contains all OrthoBench species (leakage favours OMA). FastOMA 0.5.1 drops ~5.5k genes when splitting groups (bug). We patched it and re-ran (gene coverage 79.0%→80.6%): test F 33.1 (v1 33.5), so the bug does not explain FastOMA's low score. The corrected OMA-browser labelling rule was justified by inspecting RefOG005, but it was chosen after seeing a score and moved the result in OMA's favour, so it is conservative for Ancestra.

# S4 — gene-tree inference methods for orthology (tree-building sub-benchmark)

Status: done, T+6h16 → T+6h35 (scripts/clock.sh). Author: S4 sub-agent (phylogenetics). Results: `results/S4_trees/` (`tables.md` generated by `scripts/S4_summarize.py`; `manifest.json` has code/input sha256 and commands). DEV RefOGs only (splits/orthobench_split.json); no test RefOG read.

## 0. Pre-registration (written at T+6h16 after a 2-RefOG smoke test of the plumbing, before any full result)
**Question.** Does a better tree method than localtree.py's NJ on −ln S give better ortholog/paralog labels, enough to justify its cost? Does 3Di help deep (vertebrate–invertebrate) splits?

**Units.** 34 DEV RefOGs alone (`single`); 4 DEV multi-RefOG homology components (`comp`: 005+006, 015+023, 021+068, 038+052) where the two RefOGs are deep paralogs (reference = both curated trees joined at their S5 roots). Scopes: `c3di` (set genes with a 3Di string; all arms on identical proteins), `full` (all genes; arms a, b_ft, b_iq). Sets with < 4 genes are skipped.

**Arms** (single thread each): a_nj (localtree NJ on −ln S, pipeline norm_max scores), b_ft (FAMSA + FastTree -lg), b_iq (FAMSA + IQ-TREE LG+G4 -fast), c_ft3di / c_iq3di (AA MSA mapped to 3Di; FastTree -trans / IQ-TREE with a Foldseek-derived 3Di matrix, +G4), d_part (IQ-TREE partitioned LG+G4 | 3Di+G4), d_ftcat (FastTree -lg on AA‖3Di concatenation), e_fident (Foldseek 3Di+AA all-pairs, d = −ln fident, NJ; FoldTree-style), e_fsbits (same alignments, d = −ln(bits/max self), NJ), ref (reference tree; positive control).

**Rooting/labels (identical for every arm and the reference).** Root on the edge minimising LCA-reconciliation duplications against the 12-species guide tree (run_v2 guide_tree.nwk), then losses, then tip-depth balance; species-overlap labels for all cross-species pairs.

**Truth.** Primary: `matched` = the curated reference tree pruned to the same proteins, same rooting/labelling (a perfect topology scores 1.0). Secondary: `S5` = work/S5/refog_pair_labels.parquet (curated tree rooted with its non-bilaterian outgroups; cross-RefOG pairs = paralogs).

**Primary endpoint.** Pooled pair-label accuracy, `single` sets, `c3di` scope, matched truth; Δ(arm − a_nj) with a paired bootstrap over RefOGs (B = 2000, seed 11, percentile 95% CI). Secondary: nRF and quartet distance to the reference (mean over sets), S5-truth accuracy, ortholog P/R, accuracy per pair class (mammal / vert / vert_invert / invert), `full` scope (a vs b), `comp` sets (descriptive; 4 units).

**Keep rule (pre-registered by the PI).** An arm replaces a_nj in localtree only if Δ label accuracy > 0 with the 95% CI excluding 0 **and** cost is acceptable. Cost acceptable := projected extra CPU on the OrthoBench pipeline run (15,456 tree clusters, 79,782 units in the e2e default manifest) ≤ 1 CPU-h, using a per-arm fit CPU = c0 + c1·n_leaves on the measured sets. (Note: localtree clusters are ancestral-gene units, so MSA arms would also need a unit representative; not costed here.)

**Deviations (logged, post hoc).** (1) The pre-registered linear cost fit is misspecified (CPU grows super-linearly with set size because alignment length grows too; the fitted intercept is negative and clipped to 0), so a direct measurement at localtree cluster size was added: 100 random 5-protein DEV sets (`scripts/S4_cost.py`). Both cost criteria are reported; they agree on every verdict. (2) `scripts/S4_checks.py` (ete3 RF cross-check, random-tree negative control, recomputation from saved Newick files) and the "3Di contrasts" table were added after the first results. Neither changes a metric, label or the keep rule.

## 1. Verdict
| question | answer |
|---|---|
| Does a better tree method improve orthology labels? | **Yes, modestly.** FAMSA + FastTree -lg (b_ft): label accuracy 0.928 → **0.955**, Δ +0.027 [+0.004, +0.060] (primary); nRF 0.339 → 0.198. Partitioned AA+3Di IQ-TREE (d_part): Δ +0.029 [+0.013, +0.064]. On all genes (full scope) b_ft Δ +0.034 [+0.020, +0.061]. |
| Enough to justify its cost in localtree.py? | **No (pre-registered rule).** b_ft costs 0.24 CPU-s per 5-unit cluster (median 0.14 s; ~500× NJ) → 1.01 CPU-h projected on the OrthoBench run (rule: ≤ 1 CPU-h), 6.7 CPU-h by the size fit; d_part 3.3 / 70 CPU-h. **a_nj stays in localtree.** b_ft is borderline and almost all of its cost at 5 units is process start-up, so an in-process MSA+ML implementation could pass (follow-up, §5). |
| Does 3Di help deep (vertebrate–invertebrate) splits? | **No detectable benefit.** 3Di alone is clearly worse (nRF +0.28 vs the AA tree with the same method; accuracy −0.05 to −0.07). Adding 3Di to AA: d_part − b_iq Δacc +0.009 [−0.014, +0.062], vert–invert +0.027 [−0.050, +0.076]; d_ftcat − b_ft −0.031 [−0.114, +0.014], and nRF gets *worse* (+0.10 [+0.05, +0.16]). Foldseek 3Di+AA scores in place of sequence scores (e_fsbits − a_nj): +0.003 [−0.011, +0.015]. ## 2. Data and coverage
- 34 DEV RefOGs (960 genes; 955 in the curated `trees_tight` trees after leaf-name parsing, as in S5). Sets with ≥ 4 genes: 33 full, 32 c3di (RefOG010 has 3 genes).
- 3Di (`data/structure/orthobench_3di_best.fa`, exact-sequence AFDB): **635 / 955 genes (66.5 %)**; the missing ones are mostly chicken, dog, zebrafish and rat (S6). All arm comparisons in the primary table use the same 635 proteins.
- Pipeline sequence scores (run_v2 ScoreTable, `norm_max`): 4,661 / 21,672 within-RefOG pairs (21.5 %) are unscored (DIAMOND miss or cap) and get max(d) + 1 in a_nj, exactly as in localtree. This is part of what a_nj is, not a handicap added here.
- Labelled cross-species pairs (primary scope): 9,732 (mammal 4,262; other vertebrate 4,147; **vertebrate–invertebrate 1,146**, 408 of them in RefOG054; invertebrate–invertebrate 177). Only 26.5 % are orthologs (all-ortholog baseline accuracy 0.265; random topologies 0.757–0.770, seeds 11/23/47). That is the floor; the reference tree gives 1.000.
- Components: 005+006, 015+023, 021+068, 038+052. The 016/026/027/032/037/039/058 component is entirely in test.

- Gains of b_ft/d_part come from vertebrate pairs (vert acc 0.910 → 0.959/0.943; mammal 0.951 → 0.976/0.970), i.e. **recent and 2R/teleost duplications**, not from the deep splits. ## 4. Methods / implementation notes
- **Code.** `ancestra/treebench.py` (unrooted tree, prune/join, nRF, sampled quartet distance, LCA-reconciliation rooting, S5 overlap rooting, species-overlap pair labels, paired bootstrap); `scripts/S4_trees.py` (sets, arms, evaluation → `per_set.tsv`, trees in `work/S4/sets/<set>__<scope>/<arm>.nwk`); `scripts/S4_3di_model.py`; `scripts/S4_cost.py`; `scripts/S4_summarize.py` (→ `tables.md`, `summary.json`); `scripts/S4_checks.py` (→ `checks.json`); `tests/test_treebench.py` (7 toy tests with known answers). No core file was edited; `localtree.nj`, `merge.leaf_scores` and `structure.align_pairs` are reused read-only.
- **3Di model.** No 3Di model is built into IQ-TREE 3.1.4, and the published 3DI model (Puente-Lelievre et al. 2024) was not available offline. Foldseek's 3Di log-odds matrix (bit/2, λ = 0.3516, with its background frequencies) was extracted from the foldseek binary (`results/S4_trees/mat3di.out`). It was turned into a reversible rate matrix: joint p_ij ∝ f_i f_j e^{λS_ij}, P = p/π, Q = logm(P), exchangeabilities Q_ij/π_j. 38 of 190 exchangeabilities came out non-positive from the matrix log and were floored at 1e-4 × the mean. Files: `3DI_foldseek.paml` (IQ-TREE `-m FILE+G4`) and `3DI_foldseek.fasttree.tsv` (FastTree `-trans`). This approximates a fitted 3Di model, so the 3Di-only arms may be pessimistic. But it is the same matrix Foldseek aligns with, and d_part lets IQ-TREE scale the 3Di partition's rate separately.
- **3Di alignment.** The FAMSA AA MSA columns are mapped residue-by-residue to 3Di characters (3Di length = protein length, checked). FoldTree-style arms use `foldseek structurealign --alignment-type 2` on all pairs within the set, with a DB built from AA + 3Di strings (S6 recipe; no coordinates, so no TM-score/LDDT statistics). They use d = −ln(fident) or d = −ln(bits/max self), with missing pairs set to max + 1, then the same NJ.
- **Rooting.** Species overlap alone cannot root a tree with an outgroup-free duplication (toy test `test_root_reconcile_and_labels_duplication`: the root on the outgroup and the root between the two copies both give one duplication). Reconciliation (dups, then losses) resolves this. The same rule is applied to the reference, so ref = 1.000 under matched truth.
- **Verification.** (i) Raw RF counts agree with ete3 for all 288 arm × set trees. ete3 normalises polytomous trees differently; ours always divides by 2(n−3). (ii) Pooled accuracies recomputed from the saved Newick files reproduce `per_set.tsv` exactly. (iii) Negative control: random topologies 0.76; positive control: reference 1.00. (iv) 7 toy tests pass.

## 5. Interpretation and recommendations
1. **Keep NJ in localtree.py** (pre-registered rule: no arm has both an accuracy gain with CI ∌ 0 and acceptable cost). The two arms with a significant gain (b_ft, d_part) fail the cost criterion. b_ft fails narrowly at 5 units: 1.01 vs 1.00 CPU-h.
2. The gain of a real MSA tree over score-NJ is real but small: about +0.03 pair-label accuracy and −40 % nRF on whole RefOGs. It comes from vertebrate duplications, not deep splits. In the pipeline, localtree trees are smaller (5.2 units mean) and their leaves are *ancestral genes*, so an MSA arm would also need a representative sequence or profile per unit. That is untested, and the gain on whole RefOGs is an upper bound for what localtree could get.
3. **Cheapest worthwhile follow-up:** an in-process FAMSA (pyfamsa) + FastTree-like ML on clusters ≥ 8 units only, or only at Euteleostomi/Chordata (where duplications concentrate). This would move b_ft under the cost bar. A simpler alternative, if sequence-score NJ is kept: fill the 21.5 % unscored pairs (re-align missing in-cluster pairs) before NJ. e_fsbits shows that complete but differently-scaled scores alone do not help, so this should be expected to be small.
4. **3Di for trees: negative at this resolution.** 3Di-only trees are markedly worse. AA+3Di is no better than AA with the same method (d_part ≈ b_iq; concatenated FastTree worse). FoldTree-style fident NJ gives a better topology than score NJ but not better labels. A fitted 3Di exchangeability model (published 3DI) and real-coordinate statistics (alntmscore/LDDT) are untested, and could change the 3Di-only arms.

## 6. Caveats
- Units are 32 RefOGs, and pooled pair accuracy is dominated by a few large/duplication-rich RefOGs (RefOG021: 4,478 of 9,732 pairs). The bootstrap resamples RefOGs, so the CIs reflect this, but they are wide.
- Truth labels inherit curated-tree errors. Vert–invert "paralogs" are the most suspect (S5 §2 caveat), and the S5 vs matched truths disagree on 4.5 % of pairs (rooting).
- The node was shared (load 25–35); CPU (user + sys) is reported, not wall. Tools are single-threaded; IQ-TREE `-fast`, seed 11.
- c3di excludes a third of the genes, non-randomly (chicken, dog, zebrafish, rat).

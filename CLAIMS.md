# CLAIMS.md — ledger of quantitative claims

One row per quantitative claim made in `RESEARCH_TREE.md` (plus a few from `docs/` that the tree does not yet repeat, section 9).
Created from the RESEARCH_TREE state at milestone M2 (2026-10-26, T+5h11). Statuses updated 2026-10-27 (task T5) from `docs/VERIFICATION.md` (passes 1 and 2), `docs/DISCLOSURES.md` and the evidence files; section 10 was added then. Every evidence path was checked for existence
when the ledger was written (`scripts` one-liner at the bottom). **Existence of a file is not verification of the number in it.**

## How to read this

- **dev/test** = which data the number was measured on.
  - `dev` = OrthoBench dev RefOGs (34 RefOGs, `splits/orthobench_split.json`), toy simulator, or a benchmark that has no test split.
  - `test` = OrthoBench test RefOGs or any QfO benchmark. At the M2 snapshot only one test number existed (S0 completeness, C-S0-4); after the freeze the OrthoBench and QfO final test numbers exist (section 10), all logged in `results/test_log.tsv`.
  - `n/a` = timing, data inventory or control; no dev/test split applies.
- **status** (updated 2026-10-27; the old `pending` / `verified` / `refuted` labels are replaced)
  - `VERIFIED` = independently recomputed by a reviewer who did not produce the result, and it matches. Recomputed means from raw predictions, from per-RefOG counts or from per-row data, not just reading the number from the results file.
  - `VERIFIED-WITH-CAVEAT (#n)` = recomputed and matches, but item(s) #n of `docs/DISCLOSURES.md` apply.
  - `CORRECTED` = the claim's number or statement differed from the evidence; the corrected value and its source are in the Note.
  - `UNVERIFIED` = no independent recomputation yet. Where the T5 agent read the evidence file and the number matched, the Note says so ("T5 spot-check"); that is a consistency check, not verification.
  - `RETRACTED` = contradicted by evidence. No row is retracted at present.
  - The Reviewer is named in the Note (pass 1 / pass 2 = the independent verifier of `docs/VERIFICATION.md`; T5 = the ledger-update agent) and in the Reviewer log.
- **Rule:** a claim is `VERIFIED` only when a reviewer who did not produce the result recomputes at least one number and the Reviewer log records who and when. (DESIGN.md section 6: "An agent that didn't produce a result reviews it before you rely on it.") Never edit a number to make it look better; if it disagrees with its evidence file, mark `CORRECTED` and give the evidence value.
- Numbers are copied from `RESEARCH_TREE.md` as written. Where the evidence file shows something slightly different, the Note column says so.
- Dev numbers were tuned on dev; they are expected to shrink on test. Partition sensitivity of OrthoBench dev OG-F is about +-2 to 4 points (C-CORE-12), and 34 RefOGs give wide CIs.

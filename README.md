# Orthology benchmark suite (local, reproducible)

Self-contained wrappers to evaluate orthology predictions **locally** (no docker, no nextflow,
no web upload) on:

| Benchmark | What is scored | Input format | Runner |
|---|---|---|---|
| **Open OrthoBench** (Emms & Kelly 2020) | 70 curated bilaterian RefOGs, pairwise precision/recall/F | orthogroups, one per line | `scripts/run_orthobench.sh` |
| **Quest for Orthologs 2022** (qfo/benchmark-webservice) | SwissTree, TreeFam-A, VGNC, SwissProt-IDs, GO & EC conservation, species-tree discordance (STD_*, G_STD2_*) | OrthoXML (groups/HOGs) or pairwise TSV of UniProt accessions | `scripts/run_qfo_local.sh` |

The upstream scoring code is used **unmodified**; we only replace the orchestration layer.
Raw data never lives in this repository: everything is downloaded into `$DATA_DIR`
(default `../data`, i.e. next to this repo). See `../DATA.md` for versions, checksums, licences.

## 0. Setup

```bash
export DATA_DIR=/path/to/data            # default: <this repo>/../data
bash scripts/setup_env.sh                # python 3.10 env (lxml, dendropy, biopython, jsonschema, pandas) + mafft
export PYTHON=/path/to/conda_envs/data/bin/python   # default: <this repo>/../conda_envs/data/bin/python
```

Requirements: bash, wget/curl, git, ~25 GB disk (QfO proteomes incl. DNA/isoforms 14 GB,
QfO reference data 3.3 GB, competitor predictions 3 GB). Linux x86_64 (Darwin is a static binary).

## 1. OrthoBench

```bash
bash scripts/download_orthobench.sh            # clone Open_Orthobench @872d6f3, checksums, controls
bash scripts/run_orthobench.sh my_Orthogroups.tsv my_method
# -> prints F / precision / recall / #exact RefOGs, writes results/orthobench/my_method.json
```
`scripts/orthobench_eval.py` imports the official `BENCHMARKS/benchmark.py` and calls its functions
(identical scoring); it adds JSON output, reports F=0 instead of crashing when TP=0, and (v2) writes per-RefOG
TP/FP/FN (RefOG-size normalised, as in benchmark.py), dev/test subset scores (`../splits/orthobench_split.json`;
sums of per-RefOG TP/FP/FN, verified bit-identical to benchmark.py on the full 70 at every run) and has a paired
bootstrap (`bootstrap_delta_f`, B=2000, seed 11; CLI: `orthobench_eval.py --compare A.json B.json --subset test`).
Competitor baselines (OrthoFinder, SonicParanoid2, ProteinOrtho, FastOMA): `results/orthobench_competitors/SUMMARY.md`.
Input proteomes: `$DATA_DIR/orthobench/Open_Orthobench/BENCHMARKS/Input/*.fa` (12 species, 251,378
proteins, one per gene, Ensembl release 99 IDs; FlyBase FBpp and WormBase gene IDs).

Gene coordinates for synteny: `bash scripts/download_orthobench_gff3.sh 99` (Ensembl 99 GFF3, incl.
`chr_patch_hapl_scaff` for human/mouse/zebrafish because OrthoBench contains alt-haplotype genes);
`scripts/check_gff3_coverage.py` verifies that 99.99% of input protein IDs are found.

## 2. Quest for Orthologs (QfO 2022 reference proteomes)

```bash
bash scripts/download_qfo.sh all     # proteomes 2022_02 (+updated zebrafish), webservice code @c0854a9,
                                     # Darwin binary, Zenodo reference data v2022.1 (10.5281/zenodo.10517603)
bash scripts/run_qfo_local.sh -i predictions.orthoxml.gz -n MyMethod [-o outdir] [-j 8] \
     [-b "GO EC VGNC SP SwissTrees TreeFam-A STD_Eukaryota STD_Fungi STD_Bacteria G_STD2_Luca G_STD2_Fungi G_STD2_Eukaryota G_STD2_Vertebrata"]
# -> outdir/summary.tsv (aggregate metrics), outdir/assess/*.json (OpenEBench assessment stubs,
#    incl. per-family sub-challenges), outdir/raw/<bench>/ (per-pair raw data), outdir/logs/
python scripts/compare_to_published.py outdir/summary.tsv reference_results/openebench_QfO_2022.tsv OrthoFinder
```

**Which proteomes:** the 2022 benchmark uses `qfo_release-2022_02_with_updated_UP000000437`
(78 species, 988,778 canonical proteins; checked: the benchmark `mapping.json.gz` contains
26,355 DANRE proteins = the updated zebrafish proteome, and the sum of canonical FASTA entries
equals the 988,778 proteins in the mapping). Predictions must use UniProt accessions of the
canonical `UPxxxxxx_taxid.fasta` files (OrthoXML `protId` or the two TSV columns).

**Input proteomes for a method run** (78 canonical FASTA files, UniProt headers `>sp|ACC|NAME ...`):
`find $DATA_DIR/qfo/proteomes_2022_02_updZEBRAFISH -regextype posix-extended -regex '.*/UP[0-9]+_[0-9]+\.fasta'`

**How it works without docker/nextflow:** `main.nf` is DSL1 (needs nextflow < 22.10) and runs
three docker images. `run_qfo_local.sh` executes the same steps natively and in parallel:
`validate.py` → `map_relations.py` (→ `predictions.db` for Darwin, `orthologs.db` sqlite) →
`GoTest.sh`, `EcTest.sh`, `RefPhyloTest.sh`, `SpeciesTreeDiscordanceTest.sh` (Darwin, the
static `darwin.linux64` from biorecipes.com, exactly as in `Dockerfile_qfo_darwin`) and
`vgnc_benchmark.py`, `swissprot_benchmark.py` (python). Gotchas handled: Darwin needs
`ulimit -s unlimited` and `DARWIN_ORTHOLOG_BENCHMARK_REPO_PATH`; G_STD2 needs `mafft` on PATH;
sqlite index creation needs a large `TMPDIR`. Not wired: the FAS benchmark (needs `greedyFAS`;
data are downloaded) — add if needed.

**Runtime** (24-core node, 2M–100M pairs): conversion ~1 min; GO/EC/SwissTree/TreeFam-A/VGNC/SP
< 5 min; STD_* and G_STD2_* 15 min to several hours each (thousands of tree samplings, each mafft + LSTree; slower on a shared/loaded node). For quick iteration use `-b "GO EC VGNC SwissTrees TreeFam-A"` (~5 min) and run STD/G_STD2 only on milestones. STD/G_STD2 are
stochastic (random tree samplings, no seed exposed): expect run-to-run differences within ~1 stderr.

### QfO controls
All controls are regenerated by `bash scripts/run_controls.sh [orthobench|qfo_fast|qfo_full|all]`
(summaries land in `results/controls/`).


| control | data | result |

| positive (2022, exact reproduction) | public FastOMA_v0.1.4 and OrthoFinder 2022 submissions (B2SHARE) vs OpenEBench 2022 | SwissTree, TreeFam-A, VGNC, GO, EC: **identical** to published (e.g. OrthoFinder SwissTree TPR/PPV 0.8248/0.9165, TreeFam-A 0.7367/0.9181, VGNC 0.9798/0.9971, GO 0.4869, EC 0.9311). FastOMA all STD_*/G_STD2_*: NR_ORTHOLOGS identical, RF/frac-incorrect within 1.4 stderr (`results/controls/qfo2022_FastOMA_v0.1.4_nov_vs_published.tsv`) |
| oracle (circular, validates ID mapping & metric direction) | all speciation pairs of SwissTree+TreeFam-A | SwissTree TPR 0.968 PPV 0.969; TreeFam-A TPR 0.987 PPV 1.000 |
| anti-oracle | all duplication (paralog) pairs | SwissTree PPV 0.10, TreeFam-A TPR/PPV ~0 |
| negative | 2M uniformly random inter-species pairs (seed 42) | SwissTree/TreeFam-A/VGNC/SP: 0 TP; GO 0.32 (vs 0.42–0.52 for the 20 published 2022 methods); EC 0.068 (vs 0.83–0.97); STD/G_STD2: no valid trees (999999 = no result) |

Note: SwissTree/TreeFam-A use a +1 pseudocount per family (tp=fp=fn=tn=1), so an empty prediction
gives PPV = 0.5 and TPR > 0 on small families; read them together with the raw TP/FP counts.

## 3. Published competitor results (no need to rerun competitors)

* `reference_results/openebench_QfO_2022.tsv` — all 20 participants × 13 challenges of the
  QfO 2022 event (OpenEBench `OEBE0020000003`), tidy format (x/y metric + stderr);
  `*_raw.json` is the untouched API response. `qfo2022_summary_wide.tsv`: one row per tool.
  Same for the 2018 event (`OEBE0020000001`). Refresh: `python scripts/fetch_openebench_results.py --event OEBE0020000003`.
* `reference_results/qfo2022_participant_prediction_files.tsv` — the actual prediction files of
  all 2022 participants (B2SHARE, CC-BY 4.0); download with
  `python scripts/fetch_qfo_participant_predictions.py --download OrthoFinder FastOMA_v0.1.4_nov ...`
  (md5 verified). These allow re-scoring competitors locally and per-family comparisons.

## 4. Extra data layers
`scripts/download_extra_layers.sh bgee` (Bgee v15.2 expression calls, 10 OrthoBench species),
`afdb_sizes` / `afdb <UP..._v6>` (AlphaFold DB per-proteome tarballs). QfO `_gcoord.xml`
(19 eukaryotes; Ensembl gene/transcript/translation IDs + genomic coordinates),
`_DNA.fasta` (CDS) and `_additional.fasta` (isoforms) come with the QfO proteomes.
